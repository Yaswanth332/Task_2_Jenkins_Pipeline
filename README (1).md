# DevOps Internship - Task 2: Jenkins CI/CD Pipeline

This project demonstrates a Jenkins Declarative Pipeline that checks out a Node.js application, runs automated tests, builds a Docker production image, deploys a container, and verifies its health endpoint.

## Architecture

1. A developer pushes a commit to the GitHub `main` branch.
2. Jenkins checks the configured Git repository for changes every two minutes (`pollSCM`). This avoids needing a public webhook URL for a local Jenkins instance.
3. Jenkins checks out the repository.
4. Jenkins builds the Docker `test` target. The image build installs dependencies and runs `npm test`; if a test fails, the build stops. Run `npm install` locally first and commit the generated `package-lock.json` so dependency versions are reproducible.
5. Jenkins builds the production Docker image.
6. Jenkins replaces the previous application container and starts the new container.
7. Jenkins checks `http://docker:8081/health`. The app is also available on the Windows host at `http://localhost:8081`.

## Prerequisites

- Windows 10/11 with Docker Desktop configured for Linux containers
- Git
- GitHub account
- Internet access for pulling the Jenkins, Docker, and Node.js images

## 1. Test the app locally

From the project root in PowerShell:

```powershell
npm install
# npm install generates package-lock.json; commit this file to GitHub.
npm test
npm start
```

Open `http://localhost:8080/` and `http://localhost:8080/health`.

## 2. Start Jenkins and its Docker build daemon

From the project root:

```powershell
docker compose -f jenkins/docker-compose.yml up --build -d
```

Jenkins UI: `http://localhost:8090`

The setup uses a Jenkins controller container and a dedicated Docker-in-Docker daemon. Docker-in-Docker requires privileged mode; use this only for a local learning environment and do not expose the Jenkins or Docker daemon ports publicly.

Get the initial administrator password:

```powershell
docker exec task2-jenkins cat /var/jenkins_home/secrets/initialAdminPassword
```

In the browser:

1. Paste the initial password.
2. Select **Install suggested plugins**.
3. Create the first admin user.
4. Complete the setup wizard.

Useful commands:

```powershell
docker compose -f jenkins/docker-compose.yml ps
docker compose -f jenkins/docker-compose.yml logs -f jenkins
docker compose -f jenkins/docker-compose.yml down
```

The named volumes retain Jenkins configuration and build history when the containers are stopped. Do not run `docker compose down -v` unless you intend to delete that data.

## 3. Create the GitHub repository

Create a new repository for Task 2, for example `Task_2_Jenkins_Pipeline`, as required by the internship task's submission instructions. Push this project to its `main` branch:

```powershell
git init
git add .
git commit -m "Add Jenkins CI/CD pipeline"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/Task_2_Jenkins_Pipeline.git
git push -u origin main
```

If Git is already initialized, do not run `git init` again; add the new remote or update the existing remote as appropriate.

## 4. Create a Jenkins Pipeline job

1. In Jenkins, select **New Item**.
2. Enter `task-2-nodejs-pipeline`.
3. Select **Pipeline**, then **OK**.
4. Under **Pipeline**, set **Definition** to **Pipeline script from SCM**.
5. Set **SCM** to **Git**.
6. Enter the repository URL, e.g. `https://github.com/YOUR_USERNAME/Task_2_Jenkins_Pipeline.git`.
7. For a public repository, leave credentials as **None**.
8. Set **Branch Specifier** to `*/main`.
9. Set **Script Path** to `Jenkinsfile`.
10. Save, then select **Build Now**.

The `pollSCM('H/2 * * * *')` setting in the Jenkinsfile checks for commits approximately every two minutes. For immediate push-triggered builds, configure a GitHub webhook to a publicly reachable Jenkins URL; a local `localhost` Jenkins URL cannot receive GitHub webhooks directly.

## 5. Verify the pipeline

The Jenkins Stage View should show:

- Checkout
- Build and Test
- Build Production Image
- Deploy
- Verify Deployment

A successful build should leave the app responding at:

- `http://localhost:8081/`
- `http://localhost:8081/health`

From PowerShell:

```powershell
Invoke-RestMethod http://localhost:8081/health
```

## Troubleshooting

- **Port 8090 is in use:** change the host side of `8090:8080` in `jenkins/docker-compose.yml` to another free port, e.g. `8091:8080`.
- **Port 8081 is in use:** change the host side of `8081:8081` in the `docker` service mapping and change `APP_PORT` in the Jenkinsfile to a matching inner app port. Keep both values aligned.
- **Docker CLI cannot connect:** check that the `docker` service is healthy and Jenkins has `DOCKER_HOST`, `DOCKER_CERT_PATH`, and `DOCKER_TLS_VERIFY` configured as in Compose.
- **Pipeline has no agent/executor:** ensure the controller has at least one executor available (Manage Jenkins → Nodes → Built-In Node).
- **GitHub checkout fails:** verify the repository URL and branch; for private repositories add a Jenkins username/token credential and select it in the job's SCM configuration.
